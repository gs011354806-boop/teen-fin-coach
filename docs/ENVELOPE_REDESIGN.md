# 용돈 탭 개편안: 봉투 3개 분리 + 봉투별 상세 + AI

> 상태: 기획안 (시뮬레이션 브랜치 `simulation`, 2026-11-06). 아직 `docs/FEATURES.md`에 넣지 않았다.
> 대상 화면: `pages/2_용돈봉투.py`. 계산은 `engine/envelope.py`(+ `simulate.py`, `consumption.py`, `unlock.py`), AI는 `ui_common.ask_ai`만 쓴다.

## 0. 한눈에 보기

| 구분 | 지금 | 바뀐 뒤 |
|---|---|---|
| 첫 화면 | 잔액 숫자 3개 → 목표 → 용돈 받기 → 비율 → 지출 차트·표 → 개념 카드 → 전체 내역 → 카드 추천이 한 줄로 길게 이어짐 | **봉투 카드 3장**(각각 색·아이콘·잔액·한 줄 요약) + 용돈 받기 + 나머지는 접힘 |
| 쓰기 봉투 | 첫 화면 "이번 달 가장 많이 쓴 곳은?" | 상세: **① 사용 내역 → ② 소비 분석 차트 → ③ AI 피드백** |
| 모으기 봉투 | 첫 화면 목표 진행 막대 | 상세: **① 모으기 내역 → ② 목표 → ③ AI 앞으로의 계획 요약** |
| 투자연습 봉투 → **실전 준비 자금** | 잔액 숫자만 (어디에도 쓰이지 않음) | **🔒 잠긴 봉투.** 돈은 계속 쌓이고, 3단계 + **보호자 실전 허락**이 있으면 열림. 잠긴 동안 상세는 "여는 길"(단계·습관·바로가기)을 보여 줌 (§4) |

지켜야 할 규칙 (CLAUDE.md):
- 숫자 계산은 코드로 한다. AI는 코드가 만든 사실(facts)과 판단만 받아서 문장을 쓴다. 출력은 JSON이다.
- 점수, 등수, 수익률은 화면에 없다. 종목 권유도 없다.
- AI는 버튼을 눌렀을 때만 부른다. 사용 한도를 아끼기 위해서다.
- 시연 모드에서는 저장 응답, 없으면 기본 문구를 보여 준다.

## 1. 첫 화면 (봉투 3장)

### 1-1. 배치 (모바일 폭 기준, 위에서 아래로)

```
┌ 앱 바: 용돈봉투 ─────────────── [가상 용돈 기록] ┐
│ 10-03 기준 · 데모용 가상 내역이에요.              │
├──────────────────────────────────────────────┤
│ 내 용돈 전체 93,800원                             │  ← 요약 한 줄
│ [이번 주 용돈 받음 09-28 ✓]  또는 [용돈 40,000원 받기] │  ← 용돈 받기를 위로, 작게
├──────────────────────────────────────────────┤
│ ┌───────────┐ ┌───────────┐ ┌───────────┐ │
│ │ 🛍 쓰기     │ │ 🐷 모으기   │ │ 🔒 실전 준비│ │  ← 봉투 카드 3장 (가로)
│ │ 13,800원  │ │ 48,000원  │ │ 32,000원  │ │
│ │ 이번 달    │ │ 에어팟까지 │ │ 잠김 ·     │ │
│ │ 편의점 1위 │ │ 19%       │ │ 1/3단계    │ │
│ │      ›    │ │      ›    │ │      ›    │ │
│ └───────────┘ └───────────┘ └───────────┘ │
├──────────────────────────────────────────────┤
│ ▸ 용돈 나누는 비율 (50 · 30 · 20)                │  ← 접힘
│ ▸ 내 소비에 맞는 체크카드                         │  ← 한 줄 링크 → 쓰기 봉투 안으로 이동 (§5)
│ ▸ 전체 입출금 내역                                │  ← 접힘
└ 아래 탭 바 ────────────────────────────────────┘
```

### 1-2. 봉투 카드 디자인

| 봉투 | 아이콘 | 색 계열 (`config.toml` 팔레트 안에서) | 카드 아래 한 줄 (코드가 만듦) |
|---|---|---|---|
| 쓰기 | 🛍 (또는 `:material/shopping_bag:`) | 따뜻한 주황 | "이번 달 ○○에 가장 많이 썼어요" / 지출 없으면 "아직 쓴 돈이 없어요" |
| 모으기 | 🐷 (`:material/savings:`) | 초록 | "{목표 물건}까지 {진행률}%" |
| 실전 준비 자금 | 잠김 🔒 / 열림 🌱 | 잠김: 회색 + 자물쇠 / 열림: 파랑·보라 | 잠김: "잠김 · {단계}/3단계" 또는 3단계면 "보호자 허락 기다리는 중" / 열림: "보호자 허락 {날짜}" |

- 화면 이름은 "실전 준비 자금"(좁은 카드에서는 "실전 준비")으로 바꾼다. **데이터 키 `INVEST`는 그대로 둔다.** 그래서 `allowance.csv`, 비율, 미션 계산은 바뀌지 않는다. 바꾸는 곳은 `pages/2_용돈봉투.py`의 `ENVELOPE_LABELS` 이름표뿐이다. 다른 화면(부모 리포트, 포인트 등)에 같은 이름표가 있으면 함께 맞춘다.

- 봉투 모양: 위쪽 모서리에 삼각형 덮개를 CSS `::before`로 그려 봉투처럼 보이게 한다. 이미지 파일은 쓰지 않는다.
- 색은 `.streamlit/config.toml`, 모양과 크기는 `style.css`에서만 정한다 (규칙). 카드 묶음은 `ui.columns(3, key="envelopes")`를 쓰고, 각 카드는 `st.container(key="env-SPEND")`처럼 key로 클래스를 붙인다. 색은 `style.css`의 `.st-key-env-SPEND`에서 준다.
- **터치:** 카드 전체를 버튼처럼 동작하게 한다. 각 카드 안에 `st.button(label, key="open-SPEND", width="stretch")`를 넣고 CSS로 버튼을 카드 전체에 투명하게 덮는다. 누르면 상세 화면으로 간다 (§1-3).
- 지금 상단의 잔액 숫자 3개(`card("balances")`)와 목표 막대(`card("goal")`)는 봉투 카드가 대신하므로 뺀다.

### 1-3. 상세 화면 여는 방식

| 방식 | 장점 | 단점 |
|---|---|---|
| **A. 같은 페이지 안에서 전환 (추천)** `st.query_params["env"] = "SPEND"` → 첫 화면 대신 상세를 그림 | 모바일 앱처럼 화면 전체가 바뀜. 아래 탭 바 유지. 브라우저 뒤로가기와 새로고침에서도 상태 유지. 앱 바의 뒤로(‹) 버튼으로 돌아감 | 첫 화면과 상세를 그리는 함수를 나눠야 함 |
| B. `@st.dialog` 팝업 | 구현이 빠름 | 휴대폰 목업 안에서 팝업이 목업 밖으로 넓게 뜨고, 차트와 AI 결과를 담기에 좁음 |
| C. 봉투마다 새 페이지 파일 | 파일 분리가 명확 | 홈 메뉴와 탭 구조가 늘어나고 페이지 번호 체계가 바뀜 (규칙 9: 구조 변경은 확인 필요) |

→ **A를 추천한다.** 페이지 파일 안을 다음처럼 나눈다.

```python
view = st.query_params.get("env")
if view == "SPEND":   render_spend_detail()
elif view == "SAVE":  render_save_detail()
elif view == "INVEST": render_invest_detail()
else:                 render_overview()
```

- 상세 화면 위쪽에는 봉투 색 띠와 잔액을 크게 보여 준다. 그 아래에 "다른 봉투" 작은 칩 2개를 두어 바로 옮겨 갈 수 있게 한다.

## 2. 쓰기 봉투 상세

순서: **① 사용 내역 → ② 소비 분석 차트 → ③ AI 피드백** (요청대로)

### ① 사용 내역
- 기간 칩: `이번 주 | 이번 달(기본) | 전체` (`st.segmented_control`). 계산은 `envelope.spending()`에 기간 필터를 더해 쓴다.
- 날짜별로 묶어서 보여 준다. 표보다 한 줄씩 보여 주는 쪽이 모바일에서 읽기 편하다.
  ```
  10-03 (토)
    🚌 버스카드 충전           -2,400원
  10-01 (수)
    🏪 편의점 간식             -1,800원
  ```
- 처음에는 5줄만 보여 주고 "더 보기"를 둔다. 입금(+)과 모으기에서 옮긴 돈도 회색으로 함께 보여 줘서 봉투 잔액 흐름이 보이게 한다.
- 맨 위에 "이번 달 쓴 돈 합계 / 결제 횟수"를 코드로 계산해 보여 준다.

### ② 소비 분석 차트
| 차트 | 내용 | 계산 |
|---|---|---|
| 분류별 막대 (지금 차트 유지) | 편의점·카페·디저트·식사·마트·교통·쇼핑·기타 금액 | `spending_by_category()` |
| 필요 vs 원함 비율 막대 1줄 | 편의점·카페·디저트 비중(%) vs 나머지 | `impulse_share_pct()` (19번과 같은 기준) |
| ~~또래 비교~~ (넣지 않음, §7) | 4개 분류(편의점·카페·디저트·식사·마트)의 내 결제 비중 vs 또래 비중 | `consumption.baseline()[성별]` — 이미 계산돼 있음. 등수나 "많다/적다" 판정 없이 사실만 보여 줌 |
| 주별 흐름 (선택) | 1~4주차 쓴 돈 합계 | 주 단위 합계 |

- 차트 아래에 출처를 작게 쓴다: "또래: BC카드 업종별 소비 데이터 (2026년 1~6월, 20세 미만)".
- 지금 첫 화면에 있는 개념 카드 "필요 vs 원함"은 이 차트 아래로 옮긴다.

### ③ AI 피드백 ("AI 코치에게 소비 피드백 받기" 버튼)
**코드가 미리 정하는 것 (`engine/envelope.py`에 `spend_facts()` 추가)**
- facts: 이번 달 쓴 돈, 결제 횟수, 가장 많이 쓴 분류와 금액, 원함 지출 비중, 건당 평균
- 판단 `level`: 원함 비중 40% 미만이면 `잘함`, 70% 이상이면 `연습`, 그 사이는 `보통`. 한 달 지출이 10,000원 미만이면 판단하지 않는다. 19번과 같은 기준이다.
- `try_options`: 해 볼 행동 후보 목록 (코드에 고정). 예: "편의점 가기 전에 살 것 한 가지만 정하기", "카페 대신 물병 챙기기 하루".

**AI가 쓰는 것 (새 프롬프트 `llm/prompts/spend_feedback.md`)**
```json
{"summary": "2문장: 이번 달 소비 모습 (facts 숫자 표기 그대로)",
 "good": "1문장: 잘한 점 (level이 잘함/보통일 때, 없으면 빈 문자열)",
 "try": "1문장: try_options 중 하나를 고르고 다듬은 이번 주 해 볼 것"}
```
- 검사 (`check`):
  - facts에 없는 숫자나 단위가 나오면 실패로 본다 (17번 성장 회고와 같은 방식).
  - 존댓말, 금지 표현("낭비", "한심" 같은 꾸짖음, 다른 학생과의 비교 순위)을 검사한다.
  - `try`는 try_options의 핵심 단어를 포함해야 한다.
- 기본 문구: level별 고정 문장 3개.
- 시연 모드: 학생 3명분 저장 응답을 `demo_responses.json`에 `spend_feedback` 키로 추가한다 (`data/make_demo_responses.py`).
- 결과는 세션에만 둔다. 다시 누르기 전까지 AI를 다시 부르지 않는다.
- "이번 주 해 볼 것"은 6번 미션 루프와 겹칠 수 있다. 그 주에 '원함 지출' 미션이 이미 있으면 AI 대신 그 미션 문장을 그대로 보여 준다. 중복 미션을 피하기 위해서다.

### (덤) 체크카드 추천 위치
- 카드 추천(14번)은 쓰기 지출로 계산하므로 **쓰기 봉투 상세 맨 아래**로 옮긴다. 첫 화면에는 "내 소비에 맞는 체크카드 ›" 한 줄만 남긴다.

## 3. 모으기 봉투 상세

순서: **① 모으기 내역 → ② 모으기 목표 → ③ AI 앞으로의 계획 요약**

### ① 모으기 내역
- SAVE 봉투의 입금(+)과 꺼냄(−)을 날짜순으로 보여 준다. 꺼낸 줄("모으기에서 꺼냄")은 눈에 띄게 표시하되 빨간 경고색은 쓰지 않는다.
- 주별 순증가 막대: 1~4주차에 "넣은 돈 − 꺼낸 돈". 계산은 기존 replay·parent의 저축률 계산을 재사용한다.
- 요약: "지금까지 넣은 돈 / 꺼낸 돈 / 꺼낸 횟수".

### ② 모으기 목표
- 목표 물건, 금액, 진행 막대(`goal_progress_pct`), 남은 금액.
- 예상 달성일: `simulate.alternatives()`의 A안(지금처럼)을 쓴다. 미션 탭과 같은 계산이다.
- "목표 바꾸기"는 이번 범위에서 뺀다. 지금 데이터 구조(`students.json`)를 바꾸는 일이라 따로 정해야 한다.

### ③ AI 앞으로의 계획 요약 ("목표까지 계획 세워 보기" 버튼)
**코드가 미리 정하는 것 (`spend`처럼 `save_facts()` 추가)**
- `simulate.alternatives()` 결과 A/B/C: 매주 모을 금액, 걸리는 주 수, 달성 예상일
- 지난 주들의 꺼낸 횟수, 순증가 평균
- `recommended`: 코드가 고른 안. 규칙은 "가장 빨리 끝나면서 쓰기 비율이 30% 아래로 내려가지 않는 안". AI는 이 판단을 따르기만 한다.

**AI 출력 (새 프롬프트 `llm/prompts/save_plan.md`)**
```json
{"now": "1문장: 지금 페이스 요약 (예상일 그대로)",
 "plan": "2문장: recommended 안으로 하면 언제쯤 되는지 + 지킬 행동 하나",
 "tip": "1문장: 꺼내고 싶을 때 쓸 수 있는 방법 (예: 하루 기다리기)"}
```
- 검사, 기본 문구, 시연 모드 저장은 §2-③과 같은 방식이다. 날짜와 금액은 facts 표기 그대로만 쓴다.
- 버튼 아래에 A/B/C 표를 함께 보여 준다. 숫자는 코드 계산값이고, AI 문장은 그 표를 요약할 뿐이다.
- "이 계획으로 비율 바꾸기" 버튼을 누르면 C안 비율로 `store.save_envelope_ratio()`를 호출한다. 다음 용돈부터 적용된다. 누르기 전에 확인을 받는다.

## 4. 실전 준비 자금 봉투 (잠긴 봉투 → 보호자 허락으로 열림)

### 4-1. 왜 이렇게 바꾸나
- 지금 투자연습 봉투에는 매주 용돈의 20%가 쌓인다 (민지 기준 32,000원). 그런데 **이 돈은 어디에도 쓰이지 않는다.** 투자연습 화면(1번)은 따로 정한 가상 투자금 100만 원(실제 시세 모드는 200만 원)을 쓴다.
- 이 봉투를 **"실전 준비 자금"** 으로 정한다. 연습은 가상 돈으로 하고, 이 봉투의 돈은 연습 과정을 다 마치고 **보호자가 실전을 허락해야** 열린다.
- 장점:
  - 봉투에 쌓이는 돈에 분명한 목적이 생긴다.
  - 실전 준비 단계(9번)의 마지막 3단계 "보호자에게 신청"이 지금은 신청에서 끝나는데, **보호자 허락이라는 결말**이 생긴다.
  - 열리는 조건이 수익이 아니라 연습 과정(근거 기록, 비중, 보유 기간, 미션)이라서 서비스 철학과 맞는다.

### 4-2. 여는 흐름

```
[1단계 연습용 가상 시세] ─조건─▶ [2단계 실제 시세 연습] ─조건─▶ [3단계 실전 준비 완료]
                                                         │ 학생: "보호자에게 실전 신청 보내기 (시안)" (지금도 있음)
                                                         ▼
                                     [부모 리포트] 보호자: "실전 허락하기 (시안)" / "다음에 이야기해요"   ← 새로 추가
                                                         │ 허락
                                                         ▼
                                     용돈 탭 실전 준비 자금 봉투 🔒 → 🌱 열림
```

| 상태 | 판단 (코드) | 봉투 카드 | 상세 화면 |
|---|---|---|---|
| 잠김 (1~2단계) | `unlock.stage() < 3` | 🔒 회색 · "잠김 · 1/3단계" | "여는 길" (§4-3) |
| 허락 기다림 (3단계) | `stage == 3` 이고 허락 기록 없음 | 🔒 · "보호자 허락 기다리는 중" | "여는 길" + "보호자에게 신청을 보냈어요" 안내 |
| 열림 | 허락 기록 있음 | 🌱 · "보호자 허락 10-20" | "열린 봉투" (§4-4) |

- **허락 기록은 새 파일 `data/students/guardian_approvals.csv`에 남긴다.** 열은 `student_id,date,decision(APPROVE|LATER)`이다. `unlocks.csv`의 단계 번호(1~3)는 바꾸지 않는다. 8번 화면, 부모 리포트, 효과 측정, 테스트가 그 번호를 쓰기 때문이다.
- "다음에 이야기해요"를 누르면 잠긴 채로 둔다. 벌점이나 단계 내려감은 없다. 보호자는 나중에 다시 허락할 수 있다.
- 한 번 열리면 다시 잠기지 않는다. 9번 단계와 같은 원칙이다.
- **판단은 `engine/unlock.py`에 `fund_status(stage, approvals, student_id)`를 추가해서 한다.** 결과는 `"locked" | "waiting" | "open"`이다.

### 4-3. 잠겨 있을 때 상세 화면: "여는 길"

| 순서 | 블록 | 데이터 / 계산 |
|---|---|---|
| 1 | **설명 카드:** "🔒 실전 준비 자금 32,000원이 쌓여 있어요. 연습 단계를 마치고 보호자가 허락하면 열려요." | 봉투 잔액, `fund_status` |
| 2 | **여는 길 진행:** 1→2→3단계 → 보호자 허락. 지금 위치와 다음 단계 조건 체크리스트 (충족/미충족만, 점수 없음) | `unlock.conditions()` 그대로 |
| 3 | **이번 주 투자 습관 3줄:** 근거 적은 매수, 가장 큰 종목 비중, 급하게 판 횟수 | `detect`·`unlock.max_weight_pct`·`quick_sells` |
| 4 | **바로가기:** 투자연습하러 가기 / 돌아볼 매수 N개 (실수에서 배우기) / 실전 준비 단계 화면 | `ui.service_row` |
| 5 | 쌓인 내역 (주별 입금 줄) | allowance INVEST 줄 |
| 6 | 개념 카드 1장 (분산투자 또는 투자 일지, 이번 주 연습할 것에 맞춰 코드가 고름) | `content/concepts` |

### 4-4. 열렸을 때 상세 화면: "열린 봉투" (시안)

- 맨 위 배너: "🌱 보호자가 {날짜}에 실전을 허락했어요."
- **"보호자와 함께 쓰는 실전 시작하기 (시안)"** 버튼: 실제 주문 대신 "실전 소수점 투자는 보호자 계좌와 함께 시작하는 제안 시안이에요. 이 데모는 실제 주문과 연결되지 않아요." 안내만 보여 준다. 3단계 화면의 지금 문구를 재사용한다.
- 실전 전 약속 3가지 체크 (학생이 직접 체크하고 기록만 남김): "이유를 적고 산다", "한 종목에 절반 넘게 넣지 않는다", "잃어도 괜찮은 돈만 쓴다". 이 서비스에서 연습한 습관과 그대로 이어진다.
- 쌓인 내역과 바로가기는 잠긴 상태와 같다.

### 4-5. 꼭 지킬 것
- **실제 주문, 실제 계좌, 실제 이체는 연결하지 않는다** (CLAUDE.md 기술 스택 규칙). "허락"과 "열림"은 모두 **시안 화면**이다. 버튼과 안내 문구에 "(시안)"을 붙인다.
- 넣지 않을 것: 수익률, 평가손익, 추천 종목, 다른 학생과 비교 (규칙 3·4·5).
- 봉투는 잠겨 있어도 잔액은 보여 준다. 숨기면 "내 돈이 사라졌다"로 느낄 수 있어서다.
- 잠긴 동안에도 매주 20%가 계속 쌓인다. 이게 부담이면 학생이 비율 설정에서 줄일 수 있다는 안내를 한 줄 넣는다.
- AI는 넣지 않는다. 판단이 전부 조건 충족 여부라서 코드로 충분하다.

### 4-6. 시연 (발표) 대비
- 민지는 지금 1단계라서 발표에서 "열림" 화면을 보여 줄 수 없다. **시연 모드가 켜져 있을 때만** 부모 리포트에 "시연: 3단계까지 채운 것으로 보고 허락 흐름 보기" 버튼을 둔다. 이 버튼은 세션에만 적용하고 파일에는 쓰지 않는다. 9번의 "시연 모드는 잠금 없음" 원칙과 같다.
